# 楽天ROOM 一人暮らしSALE 投稿メーカー

楽天ROOMの**商品紹介文**と、それを告知する**X（旧Twitter）の投稿文**を作るツール。
一人暮らし向けのSALE商品に特化していて、iPhoneのSafariから使える。

ネタ出し → 紹介文 → X投稿 → 投稿前チェック まで、1つの画面で完結する。

<!-- 画面の流れ -->
| ネタ出し | ROOM紹介文 | X投稿 | チェック |
| --- | --- | --- | --- |
| 季節・カテゴリ・マニアック度で題材を出す | 3段構成で3パターン生成 | 5つの型で生成 | 文字数・NG表現・PR表記 |

---

## なにが自動化されるか

**文字数の制約を機械が守る**
- ROOMの紹介文は500文字を超えると投稿できない → 超えたら後ろのブロックから自動で削る
- ROOMの一覧では冒頭42文字しか表示されない → 1行目が42文字に収まる候補を優先し、生成結果には**42文字の位置を色で表示**する
- Xは「重み付き280」で、日本語は1文字＝2、URLは長さに関係なく23 → 正確に数えて、超える場合はタグから削る

**規約と法令のチェック**
- 薬機法・景品表示法・楽天ROOM規約で引っかかりやすい27の表現を検査し、理由と言い換え案を出す
- ステマ規制のPR表記（必須になるケース、使える言葉、置く位置）を判定する
- 2025年8月の規約改定（他人の投稿のリプ欄へのリンク掲載禁止）を、リンクの置き方を選んだときに警告する

**通常商品とセール商品を切り替えられる**
- 「セール商品」を選ぶと通常価格・セール価格の欄が出て、紹介文の冒頭が**価格の変化から始まる**（例：`19,800円→9,900円（50%OFF）。部屋干しが数時間で乾き切る`）
- 42文字に収まるよう、価格表記を「矢印＋割引率」「矢印のみ」「半額の◯◯円」から自動で選ぶ。訴求が消えるくらいなら価格表記のほうを短くする
- X投稿にも同じ価格表記が入る
- 割引率は切り捨てで計算する。四捨五入だと49.6%が50%になり、値引き率を実態より大きく見せてしまうため
- 通常価格とセール価格が逆なら要修正として弾く。二重価格表示の注意（比較価格はセール直前8週間のうち4週間以上その価格で売られていた必要がある）を入力欄の直下に出す

**書き方の型を2つから選べる**
- **インフルエンサー型（既定）** … 実際に伸びている投稿を分解した並び。キャッチ → 署名タグ → 誰向けか → 区切り線 → ✔リスト → 体験談 → 誘導文 → タグ
- **レビュー型** … イントロ → メリット → デメリット → クロージングの3段構成
- 署名タグ（`#◯◯オリ写`）、アクセント絵文字、誘導文、タグ後ろの検索ワードを設定できる
- ✔の行末の飾りは全行には付けず、空文字を混ぜて散らす（機械的に見えないように）
- 体験メモは空行で段落に割る。文字は一切いじらないので、書いたものがそのまま出る
- タグはインフルエンサー型で8個まで。末尾2語は `#` を付けない平テキストにして、読み手をタグ一覧へ逃がさない

**文章の型**
- 人気ルーマーの紹介文に共通する3段構成（イントロ → メイン → クロージング）をテンプレート化
- 文体5種類 × 長さ3種類。同じ商品でも別の切り口で出せる
- デメリットを対処法とセットで書く型を標準にしている（信憑性が上がるため）

**ネタ出し**
- 一人暮らし向け商品61件の辞書つき。それぞれに「悩み・訴求・正直なデメリット・使用シーン・タグ」を持たせてある
- 王道 / 知る人ぞ知る / マニアック の3層で絞れる
- まとめ投稿用のテーマ10種類

根拠と出典は [`docs/research.md`](docs/research.md)、毎日の回し方は [`docs/playbook.md`](docs/playbook.md) に書いた。

## iPhoneで使う

### 方法1：GitHub Pagesに公開して、ホーム画面に追加する（おすすめ）

1. GitHubのリポジトリ設定で **Settings → Pages → Source を「GitHub Actions」** にする
2. `main` にpushすると [`.github/workflows/pages.yml`](.github/workflows/pages.yml) が動いて公開される
3. iPhoneのSafariで公開URLを開く
4. 共有ボタン → **「ホーム画面に追加」**

追加するとアプリとして起動し、Service Workerが効くので**電波がなくても使える**。

### 方法2：ファイル1つを保存して開く

```bash
npm run build      # dist/index.html ができる（1ファイル完結・約126KB）
```

`dist/index.html` をiPhoneの「ファイル」アプリに保存し、Safariで開く。サーバーは要らない。

### 方法3：同じWi-Fiのパソコンから配信する

```bash
npm run serve      # 表示されたIPアドレスのURLをiPhoneで開く
```

## iOSショートカットとつなぐ

楽天市場アプリの共有シートから、商品ページのURLを持ってきて起動できる。

ショートカットの中身：

1. アクション「**共有シートから受け取る**」（受け取るタイプ：URL）
2. アクション「**URLを開く**」に次を入れる（`ショートカットの入力` を変数として差し込む）

```
https://<公開したURL>/?url=[ショートカットの入力]
```

商品名も渡したいときは `?name=商品名&url=...` の形にする。
対応しているパラメータ：`name` / `url` / `cat` / `off` / `pain` / `hook` / `price`（通常価格） / `sale`（セール価格）

`price` か `sale` が付いていると、セール商品として開きます。

起動すると「ROOM文」タブが開いた状態でフォームが埋まる。

## パソコンから使う（CLI）

```bash
node src/cli.js today                                  # 今日狙えるセールと季節
node src/cli.js ideas --season winter --maniac 2       # マニアック枠のネタを出す
node src/cli.js themes                                 # まとめ投稿のテーマ一覧
node src/cli.js room --id l04 --signature "まなと。オリ写⸜❤︎⸝" --keywords "ひとり鍋,冬支度"
node src/cli.js room --id l04 --layout review --tone real --event marathon --off 30
node src/cli.js x --id l04 --url "https://room.rakuten.co.jp/..." --link selfReply
node src/cli.js check --file draft.txt --mode room
node src/cli.js --help
```

`--id` は同梱の商品辞書のID。`--search 部屋干し` のようにキーワードでも引ける。
辞書にない商品は `--name` と `--pain` `--hook` `--merits` などを直接渡す。

## 構成

```
src/
  data/
    products.js     一人暮らし向け商品61件（悩み・訴求・デメリット・タグ）
    tones.js        文体5種類とX投稿の型5種類
    hashtags.js     ROOM/X別のタグ辞書と組み立て
    saleEvents.js   セールイベントと、日付からの当たり付け
    layouts.js      書き方の型（並び・区切り線・誘導文・絵文字）
    ngwords.js      薬機法・景表法・ROOM規約のNG表現27件
  core/
    textLength.js   ROOM 500/42文字、Xの重み付き280の計算
    rng.js          種を指定できる擬似乱数（同じ入力で同じ文章が出る）
    price.js        セール価格の計算と、冒頭に置く価格表記の組み立て
    validate.js     文字数・NG表現・PR表記のチェック
    roomComment.js  ROOM紹介文の生成
    xPost.js        X投稿の生成
    ideas.js        ネタ出しとまとめ投稿テーマ
  cli.js            コマンドライン
web/                iPhone向けのWebアプリ（PWA）
scripts/
  build.mjs         dist/index.html（単一ファイル版）を作る
  gen-icons.mjs     ホーム画面用のPNGアイコンを生成
  serve.mjs         手元確認用の最小サーバ
docs/
  research.md       仕様の根拠と出典
  playbook.md       毎日の運用手順
```

依存パッケージはなし。Node.js 20以上で動く。

```bash
npm test           # 80件のテスト
npm run build      # dist/ を作る
```

テストでは、全商品 × 全文体 × 全長さの組み合わせで
500文字を超えないこと・文法が壊れる連結が起きないこと・生成物に要修正の指摘が出ないことを毎回確認している。
セール商品についても、全商品 × 全文体 × 3つの価格帯で1行目が42文字に収まることを検証している。
インフルエンサー型は、実例と同じ材料を入れたときに同じ並びで出ることをテストで固定している。

## このツールが肩代わりしないこと

- **写真** — ROOMのランクB以上（報酬ボーナス +1〜3%）とピックアップ欄の掲載は、どちらもオリジナル写真が条件。ここは撮るしかない
- **体験** — 「自分の体験メモ」欄に書いた文章は加工せずそのまま本文に入る。他人の投稿との差になるのはここだけ
- **最終確認** — 生成した文章は投稿前に必ず自分で読む。NG表現の辞書は完全ではないし、規約も変わる
