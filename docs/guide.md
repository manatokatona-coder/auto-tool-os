# Claudeを使ったアフィリエイトブログ「リサーチ→記事生成→投稿→改善」自動化ガイド

## 0. 全体設計

パイプラインは大きく6段階です。それぞれ「人がやる部分」と「Claudeにやらせる部分」を分けて設計するのがポイントです(全自動にすると品質が崩壊しやすいため)。

```
① キーワード/市場リサーチ
       ↓
② 記事構成(アウトライン)設計
       ↓
③ 本文生成(Claude API)
       ↓
④ ファクトチェック・SEO調整・E-E-A-T補強 ★人の確認を必ず挟む
       ↓
⑤ WordPress等への投稿(自動 or 予約)
       ↓
⑥ アクセス解析→改善提案(Claudeに分析させる)→②へ戻る
```

必要なもの一式:
- Claude API keyまたはClaude.aiのProプラン
- キーワードデータ取得手段(ラッコキーワード、Googleキーワードプランナー、Ubersuggest、Ahrefsなど。無料でも可)
- WordPressサイト(REST APIまたはアプリケーションパスワードが使えるもの)
- Google Search Console / GA4(改善サイクル用)
- Python実行環境(自動化スクリプト用。Node.jsでも可)

このリポジトリでは、①〜③・⑥をスクリプト化し(`scripts/`)、④・⑤の投稿判断は
必ず人が行う設計にしています。実際の使い方は `README.md` を参照してください。

---

## ① キーワード・市場リサーチ

### やること
1. 狙う商品/ジャンルを決める(楽天・Amazon・A8.netなどの案件から選定)
2. 関連キーワードを洗い出す(サジェスト、共起語、競合サイトの見出し)
3. 検索意図を分類する(購入直前/比較検討/情報収集)
4. 競合記事の強み弱みを整理する

### Claudeの使い方
検索結果や競合記事のテキストをClaudeに渡し、以下のようなプロンプトで整理させます。

```
以下は「[キーワード]」で上位表示されている記事5本のタイトルと見出し構成です。
{競合記事のタイトル・見出しを貼り付け}

これらを分析し、
1. 共通して扱われているトピック
2. どの記事にも書かれていない/弱い切り口(差別化ポイント)
3. 想定される検索意図(比較/購入直前/情報収集のどれか)
4. この記事で狙うべきタイトル案を3つ
を出してください。
```

**注意**: Claude単体ではリアルタイムの検索順位や検索ボリュームは分からないため、実際のSERPデータやキーワードツールの出力を貼り付けて「分析・要約」をさせる使い方が基本です。Claudeに「検索1位は〇〇です」のような事実を生成させない(ハルシネーションのリスク)。

## ② 記事構成(アウトライン)設計

### やること
- 記事の見出し構成(H2/H3)を決める
- 各見出しで書くべき要素(データ、比較表、体験談の挿入位置)を決める
- E-E-A-T(経験・専門性・権威性・信頼性)をどこで担保するか設計する

### サンプルプロンプト
```
テーマ: [商品/サービス名]の比較レビュー記事
想定読者: [ペルソナ]
狙うキーワード: [メインKW]、[サブKW]

以下条件でアウトラインを作成してください。
- H2は5〜7個、各H2にH3を2〜3個
- 「比較表を入れる箇所」「著者の使用体験を入れる箇所」「デメリット・注意点」を明示
- 記事末尾にCTA(購入リンク誘導)の位置を指定
- 競合との差別化ポイント(前段のリサーチ結果)を必ず1つ以上反映
```

ここで**必ず人が確認**: 実体験に基づく記述を入れる箇所を決めておかないと、後工程で「使ったことがないのに断定的なレビュー」になり、景品表示法・薬機法・ステマ規制(アフィリエイトである旨の表示義務)に抵触するリスクがあります。

## ③ 本文生成(Claude API)

Claude APIを使ってアウトラインから本文を生成します。サンプルコードは `scripts/03_generate_article.py` を参照してください。ポイント:

- **1回のAPI呼び出しで全文を作らない**。セクションごとに生成→レビュー→次のセクション、という分割生成にすると、後で手直ししやすく、事実誤認も減らせます。
- プロンプトには「あなたの実体験談として書かない(著者が実際に体験していない場合)」「断定できない情報は『〜と言われている』とぼかす」など、正直さを担保する指示を入れる。
- 生成後、価格・スペック・キャンペーン情報など時事性の高い数値は必ず一次情報(公式サイト等)で人が裏取りする。

---

## ④ ファクトチェック・SEO調整

### チェック項目(Claudeにもレビューさせられる)
- タイトルにメインキーワードが含まれているか
- メタディスクリプション(120字前後)
- 見出し(H2/H3)の論理的な流れ
- 内部リンクの提案(サイト内の関連記事へ)
- 画像alt文言の提案
- 薬機法・景品表示法・ステマ規制(アフィリエイトである旨の明記)に触れる表現がないか

```
以下の記事本文をレビューしてください。
1. 誇大・断定的すぎる表現(効果を保証するような文言)がないか指摘
2. アフィリエイトリンクである旨の表示が必要な箇所を指摘
3. メタディスクリプション案を120字程度で3案
4. 内部リンクを入れるべき箇所を3つ提案
```

**この段階は自動化せず、必ず人間が最終確認する工程として設計してください**(Googleのスパムポリシーは「大量生成された低品質・無益なコンテンツ」を明確にペナルティ対象としています)。

## ⑤ 投稿の自動化(WordPress例)

WordPress REST API + アプリケーションパスワードを使えば、下書き/予約投稿までスクリプトから行えます。サンプルは `scripts/05_post_to_wordpress.py` を参照。

流れ:
1. WordPress管理画面 → ユーザー → アプリケーションパスワードを発行
2. スクリプトから `POST /wp-json/wp/v2/posts` にタイトル・本文・ステータス(`draft` or `future`)を送信
3. 最初は必ず `status: "draft"` で送り、人が最終チェックしてから公開に変更する運用を推奨

## ⑥ 効果測定・改善サイクル

- Google Search Console API / GA4 APIで「掲載順位」「クリック率」「離脱率」等を取得
- そのデータをClaudeに渡し、「順位が伸びていない記事のテコ入れ案」「クリック率が低いタイトルの改善案」を出させる

```
以下はGSCの記事別データです(記事URL/表示回数/クリック数/平均掲載順位)。
{データ貼り付け}

CTR(クリック率)が2%未満かつ掲載順位が10位以内の記事を抽出し、
タイトル・メタディスクリプションの改善案を出してください。
```

このサイクルを週1〜月1で回すと、記事の書きっぱなしを防げます。サンプルは `scripts/06_analyze_performance.py` を参照。

---

## 全体を繋ぐ(スケジューリング)

- 個人の小規模運用なら「手動でスクリプトを順番に実行」で十分
- 本格的に自動化するなら GitHub Actions のcronジョブ(`.github/workflows/generate_drafts.yml`)で
  「①〜③まで自動生成→下書き保存→PRで通知だけ来て④以降は人が対応」という**半自動**構成が現実的です
  (全自動公開はリスクが高いため推奨しません)。

## 重要な注意点(必ず読んでください)

1. **収益を保証する情報ではありません**。SNS上の「7日で23万円」等の体験談は再現性が検証できないため、投資判断の根拠にしないでください。
2. **Googleの品質に関するポリシー**は、検索順位操作を主目的とした大量生成コンテンツを明確に対象としています。この仕組みは「効率化のための下書き支援」として使い、最終的な品質担保・事実確認は人間が行う設計にしてください。
3. **法令面**: アフィリエイトである旨の表示(ステルスマーケティング規制)、誇大表現の禁止(景品表示法)、健康食品等なら薬機法にも注意が必要です。判断に迷う場合は専門家(弁護士等)に確認してください。私は法律の専門家ではないため、これは一般的な情報であり法的助言ではありません。
4. **著作権**: 競合記事の文章をそのままコピーして生成させることは著作権侵害になり得ます。あくまで「構成の参考」「差別化ポイントの分析」に使ってください。
